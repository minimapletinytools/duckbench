Duckbench sign-in and MCP setup

Duckbench has its own Cloudflare Worker, duckbench-backend. It uses Kigumi’s existing Supabase project for GitHub and Google login and the same account balance for chat. The browser MCP relay runs on the Duckbench Worker.

  1. Add the sign-in redirects for the Duckbench versions you use.
  2. Add the two Worker secrets to enable built-in chat.
  3. Connect and verify MCP in the browser or desktop app.

Enable chat on the Duckbench Worker

In Cloudflare, open Workers & Pages → duckbench-backend → Settings → Variables and Secrets. Add each value with type Secret and deploy the settings. You can also use the terminal commands below to enter the values at Wrangler’s prompts.

SUPABASE_SERVICE_ROLE_KEY
Use the shared Kigumi project’s legacy service_role key from Project Settings → API Keys. This Worker uses it to settle chat charges against the shared balance. Open project API keys.
OPENROUTER_API_KEY
Use an OpenRouter key for model requests. A dedicated Duckbench key lets you set its own spending limit. Open OpenRouter keys.
# From the duckbench folder
cd ../kigumi-backend
npx wrangler secret put SUPABASE_SERVICE_ROLE_KEY --config wrangler.duckbench.jsonc
npx wrangler secret put OPENROUTER_API_KEY --config wrangler.duckbench.jsonc

Enter the values directly in Cloudflare or the terminal prompt. The frontend uses only the public Supabase URL and publishable key. The MCP signing secret belongs to the Worker and is separate from these chat credentials.

Connect a desktop MCP client

From the duckbench folder, run npm run desktop. For a fresh checkout, install the dependencies first with npm ci and uv sync --locked. Open a project and follow Connect and verify. The desktop app serves MCP on your machine. Sign-in is optional unless you also want the built-in chat.

Add Duckbench’s sign-in redirects

  1. Open Authentication → URL Configuration in Kigumi’s existing Supabase project. Open Kigumi’s Supabase settings.
  2. Under Redirect URLs, choose Add URL for each Duckbench version you plan to use. Paste each address exactly, including the trailing slash where shown.
Local browser
http://localhost:5173/
Hosted browser on GitHub Pages
https://minimapletinytools.github.io/duckbench/
Desktop chat sign-in
http://127.0.0.1:43781/auth/callback

These are additional entries in the project’s redirect list. Kigumi’s existing GitHub and Google OAuth apps already send sign-ins to Supabase. Supabase then sends the user back to Duckbench. The existing Site URL and provider credentials work for this setup. Supabase redirect URL guide.

Try it locally

With dependencies installed, run this from the duckbench folder. The fixed host and port match both the redirect entry and the Duckbench Worker configuration.

npm run dev -- --host localhost --port 5173 --strictPort

Open the local app, choose Agent, and sign in with GitHub or Google. You should return to Duckbench and see your account in the panel. Open local Duckbench.

Publish and check the hosted app

The Duckbench Worker configuration includes the GitHub Pages origin and local development origins. For future backend releases, run npm run deploy:duckbench in kigumi-backend. This deployment uses the existing Supabase schema.

Publish the updated frontend through Duckbench’s Deploy GitHub Pages workflow. Open the app at the exact redirect URL and sign in. Then connect MCP below. Open hosted Duckbench.

The public models endpoint is a quick Worker health check. It returns JSON even before model billing is configured. To test chat itself, sign in to the app with an account that has Kigumi credit and send a message. Check the Duckbench Worker.

Connect and verify

  1. In Duckbench, open the project you want to share. In the browser, sign in first.
  2. Choose Agent → MCP connection → Enable MCP server → Copy for all agents.
  3. Paste the setup prompt into your external agent. For manual setup, click your client’s name and follow the instructions beneath the buttons. Choose URL and token for other Streamable HTTP clients. The setup contains a session credential for the intended client.
  4. Keep Duckbench open. Ask the client to call workbench_state and tell me the active filename. The returned filename should match the Duckbench editor. Switching projects or disconnecting ends the session.

Open a workspace or model in Duckbench Viewer

The browser opens Default Project in Monaco. The desktop app opens the same workbench. Choose Open workspace… to select a folder on disk, then use the explorer to open or create files and folders.

On Apple silicon, open release/viewer/mac-arm64/Duckbench Viewer.app and choose Open file. Select a STEP, STP, STL or Duckbench viewer HTML file. The viewer runs offline and needs no account or cloud setup.

To share a model from the workbench, build it and choose Preview → Viewer HTML ↓. The recipient can open the exported HTML directly in their browser. For an editable project backup, choose Export ZIP in Explorer.

To launch the desktop viewer from the project folder, install the dependencies and run these commands. Use npm run package:viewer to build a local application bundle.

npm ci
uv sync
npm run viewer
